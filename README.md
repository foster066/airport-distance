# Сервис вычисления расстояния между аэропортами
Данный проект создан как демо разработки простого микро-сервиса, разработанного с учетом горизонтального масштабирования.

# Бизнес требования
Сервис должен осуществлять вычисление расстояния в милях между двумя аэропортами, указанными в параметрах для вызова формате ИАТА кода.

# Нефункциональные требования
1.	Аутентификация и авторизация не требуется
2.	Нагрузка ожидается в количестве 1000 RPS
3.	Горизонтальное масштабирование 
4.	Написание юнит тестов с покрытием не менее 60%
5.	Протокол взаимодействия HTTP REST

Запросы от пользователей либо от любых автоматических систем и API из сети Internet поступают на внешних Reverse Proxy, в котором также осуществляется балансировка нагрузки. Reverse proxy расположен с промежуточной DMZ зоне, отделенной от внутренней сети компании. Далее запросы в Reverse Proxy поступают на экземпляры сервиса Distance Service, который непосредственно осуществляет вычисление расстояния. **Distance Service** обращается к внешнему API, который предоставляет справочную информацию об аэропорте в частности их координаты. Для сокращения количества обращений к внешнему API используется Persistent Cache.

## Выбранные компоненты архитектуры
1.	В качестве **Reverse proxy** используем YARP, т.к. он легко интегрируется в .NET решения, гибок в настройках за счет конфигурации, имеет хорошую производительность.
2.	**Distance Service** – разрабатываем на .NET 9 Web API, используя .NET Aspire
3.	В качестве **Persistent Cache** используем Redis из-за простоты интеграции и приемлемой производительности
4.	В качестве **External API** используем решение от компании Continent Express

## Описание классов:
1.	**DistanceController** – входная точка приложения для REST HTTP API. Осуществляет валидацию входных данных
2.	**DistanceCalculatorService** – основной сервис, в котором реализована логика взаимодействия между сервисами
3.	**DistributedSimpleCache** – абстракция над кэшом, чтобы не завязываться на имплементацию кэша.
4.	**HybridCache** – Имплементация кэша, используется Redis для распределенного хранения значений результатов от внешнего сервиса для уменьшения нагрузки.
5.	**ContinentAirportInformationService** – имплементация получения информации об аэропорте. Используется HTTP вызов сервиса от компании Континент Экспресс.
6.	**MilesCoordinatesCalculator** – вычисляет расстояние в милях между двумя парами GPS координат, используя формулу Haversine, с переводом километров в мили

# Протокол взаимодействия с сервисом
Для получения расстояния между аэропортами необходимо отправить следующий запрос к сервису или прокси:
```
POST http://localhost:5282/api/distance/airports
Content-Type: application/json
{
  "IataCodeFirst": "DME",
  "IataCodeSecond": "VKO"
}
```
Формат ответа:
```
{
  "distance": 27.09
}
```
# Горизонтальное масштабирование
Каждый сервис имеет возможность размещаться в docker контейнере, поэтому мы можем создать дополнительные экземпляры сервиса **Distance Service**, указать их в списке хостов в Load Balancer и обеспечить горизонтальное масштабирование. 
Распределенный кэш HybridCache также имеет возможность масштабирования через создание кластера Redis

# Методика тестирования
Для тестирования сервиса были созданы .http файлы в проекте **LoadBalancer** – **AviaExpress.AiportsDistance.LoadBalancer.http**. В нем указаны основные сценарии тестирования с учетом ошибочных для проверки валидации. Для запуска проекта необходимо открыть решение AirportsDistance.sln в Visual Studio 2022 с установленным .NET 9, далее запустить решение, нажав Ctrl+F5 или Debug -> Start Without Debugging. Далее открыть файл AviaExpress.AiportsDistance.LoadBalancer.http и нажаать на ссылку Send request около каждого запроса.
Также решение можно запустить через команду dotnet run из папки проекта AviaExpress.AirportDistance.App.Host
